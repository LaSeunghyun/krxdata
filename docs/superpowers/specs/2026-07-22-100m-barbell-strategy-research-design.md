# 600만원→1억원 바벨 전략 연구 설계

- 날짜: 2026-07-22
- 대상 저장소: `C:\claudeT\files`
- 상태: 사용자 설계 승인 후 문서화
- 적용 범위: 로컬 연구·백테스트·shadow 검증
- 제외 범위: VM 배포, `stock-live.service` 재시작, 실계좌 설정 변경

## 1. 목표와 제약

초기자본 600만원을 추가 입금 없이 5년 이내에 1억원으로 성장시키는 전략을 찾는다. 필요한 연복리수익률은 다음과 같다.

```text
(100,000,000 / 6,000,000)^(1/5) - 1 = 75.54%
```

수익 목표보다 원금 보전과 재현성을 우선한다.

- 검증되지 않은 전략은 실계좌에 반영하지 않는다.
- 모든 후보는 비용 반영 백테스트와 `subsample 0.8` 몬테카를로를 통과해야 한다.
- 레버리지, 신용, 미수, 추가 입금은 사용하지 않는다.
- 단일 경로의 우수한 결과는 채택 근거가 아니다.
- 통과 전략이 없으면 결과를 `검증된 해법 없음`으로 판정한다.

## 2. 핵심 판단

현행 combo-v2는 지금까지 테스트한 후보 중 가장 나았지만, 라이브 정합 조건에서 관측된 성과만으로 5년 목표를 달성할 수 있다고 볼 수 없다. 따라서 combo-v2를 즉시 교체하거나 공격적으로 증액하지 않고 다음 세 연구를 같은 검증 틀에서 비교한다.

1. 제한된 전략 토너먼트
2. combo-v2의 사전 등록된 개선안
3. 고수익 집중전략의 반증 실험

기본 자본 구조는 `코어 2/3 + 위성 1/3` 바벨로 한다. 다만 이는 안전을 보장하는 구조가 아니라, 공격 전략의 손실 전염을 제한하기 위한 위험 예산이다.

## 3. 자본 구조

### 코어: 400만원

코어는 원금 방어와 복리 지속을 담당한다.

- 레버리지 없음
- 후보 단독 MDD 목표 15% 이하
- 하락 레짐에서는 현금 보유 허용
- 코어 후보: live-parity combo-v2, 중기 추세/현금, 품질·모멘텀

### 위성: 200만원

위성은 5년 목표에 필요한 비대칭 수익 가능성을 시험한다.

- 후보: 유동성 상위 종목의 집중 신고가 모멘텀
- 한 번에 1~2종목까지만 보유하되, 기존의 `slots=1 전액 몰빵`은 재시험하지 않는다.
- 위성 자체 MDD가 35%를 넘으면 신규 진입을 중단하고 현금화한다.
- 코어 자금을 위성 손실 보충에 사용하지 않는다.

### 결합 규칙

- 초기 배분은 코어 2/3, 위성 1/3이다.
- 분기말에만 2:1로 리밸런싱한다.
- 위성 위험 중단 상태에서는 위성 몫을 현금으로 유지한다.
- 일별 자산곡선을 합산한 전체 포트폴리오를 최종 판정 대상으로 삼는다.

코어가 연 10~15%라면 전체 연 75.54%를 만들기 위해 위성은 대략 연 200% 수준이 필요하다. 따라서 바벨은 목표 달성을 쉽게 만드는 장치가 아니며, 공격 전략의 생존 가능성을 정직하게 측정하는 구조다.

## 4. 후보 전략과 실험 예산

과최적화를 막기 위해 전략군별 최대 3개, 전체 최대 9개 후보만 허용한다. 모든 후보와 결과는 성공·실패 여부와 관계없이 실험 원장에 기록한다.

### A. 제한된 전략 토너먼트

- A1: 현행 live-parity combo-v2
- A2: 절대 모멘텀 기반 중기 추세/현금 전략
- A3: point-in-time 데이터가 확보되는 경우에만 품질·모멘텀 월간 전략

### B. combo-v2 개선

- B1: 현행 설정 고정 기준선
- B2: 기존 shadow 변동성 스로틀을 이용한 노출 축소안
- B3: 진입 규칙은 유지하고 보유·청산 시간축만 사전 등록한 개선안

변형 간에 여러 파라미터를 동시에 바꾸지 않는다. 기존에 실패한 다음 실험은 재시험하지 않는다.

- `slots=1` 전액 집중
- 러너 비율 1/3
- 하락예측 harvest
- 유니버스 100/200 확대
- 로테이션 또는 최약 슬롯 교체

### C. 공격형 반증 실험

- C1: 유동성 상위군의 120일 신고가 집중 모멘텀
- C2: C1에 시장 레짐 게이트 적용
- C3: C2에 위성 손실 중단 규칙 적용

C군은 높은 백테스트 CAGR만으로 채택하지 않는다. 전체 포트폴리오의 몬테카를로 위험 기준을 만족하지 못하면 `REJECTED`다.

## 5. 데이터 설계

현재 반복 사용한 2023~2026 구간은 연구 과정에 노출되었으므로 완전한 미사용 표본으로 취급하지 않는다.

### 필수 데이터 조건

- 목표 기간: 가능한 범위에서 2016~2026년 일봉
- 당시 시점의 시가총액·거래대금·상장 상태를 반영한 point-in-time 유니버스
- 상장폐지·거래정지 종목 포함
- 액면분할, 병합, 권리락 등 기업행사 보정
- 실제 시장 구분에 맞는 수수료·세금
- 신호 시점 이후 가격만 사용하는 체결 모델

point-in-time 유니버스나 상장폐지 데이터가 확보되지 않은 후보는 결과가 좋아도 `LIVE_ELIGIBLE`이 될 수 없다.

### 기간 검증

- 고정 파라미터를 먼저 등록한다.
- 순차 walk-forward로 개발 구간과 평가 구간을 분리한다.
- 2023~2026 결과는 보조 증거로 표시한다.
- 백테스트 통과 후 최소 60거래일의 실시간 shadow 검증을 추가한다.

이미 확인한 기간을 새 OOS 결과처럼 재사용하지 않는다.

## 6. 비용과 체결

백테스트와 라이브가 같은 후보 생성, 주문 가능 수량, 비용 계산을 사용해야 한다.

- 매수·매도 수수료 반영
- 시장별 거래세 반영
- next-open 또는 라이브와 동등한 체결 기준 사용
- 최소 호가 단위 반영
- 기준 슬리피지와 2배 비용 스트레스 제공
- 거래대금 30억원 이상 필터를 신호 시점 데이터로 계산
- 미체결, 갭, 거래정지를 낙관적으로 처리하지 않음

## 7. 검증 파이프라인

각 후보는 다음 순서로 검사한다.

1. 데이터 무결성과 look-ahead 검사
2. 기준 백테스트
3. 순차 walk-forward
4. `subsample 0.8 × 20시드` 몬테카를로
5. 비용 2배, 슬리피지 악화, 급락 구간 스트레스
6. 코어·위성 결합 포트폴리오 평가
7. 통과 후보의 60거래일 shadow 검증

몬테카를로는 단순 거래 순서 섞기만으로 끝내지 않고 시계열 군집 손실을 보존하는 block 방식도 함께 산출한다. 두 방식 중 더 나쁜 결과를 판정에 사용한다.

## 8. 판정 기준

### 전체 포트폴리오 필수 기준

- CAGR 75.54% 이상
- MC MDD 중앙값 20% 이하
- MC 최악 시드 MDD 30% 이하
- 비용 2배 스트레스의 종료자산이 초기 600만원 이상
- 비용 2배 스트레스 MDD 35% 이하
- 파산 시드 0개
- 레버리지·추가 입금 없음

### 결과 등급

- `LIVE_ELIGIBLE`: 데이터 신뢰성, 수익 목표, 위험 기준, 스트레스, shadow를 모두 통과
- `SHADOW_ONLY`: 데이터와 위험 기준은 통과하지만 CAGR 75.54% 또는 shadow 기간이 미달
- `REJECTED`: MDD, 스트레스, 데이터 무결성 중 하나라도 실패

코어 후보 자체는 MDD 15% 이하를 목표로 비교하지만, 최종 승인은 전체 포트폴리오 기준으로만 결정한다.

## 9. 결과 산출물

각 실행은 재현 가능한 설정과 함께 다음을 저장한다.

- 전략명과 설정 해시
- 사용 데이터 범위와 유니버스 버전
- CAGR, MDD, PF, 승률, 거래 수
- 연도별·레짐별 성과
- MC 중앙값, 최악 시드, 파산 시드 수
- 비용·슬리피지 스트레스 결과
- 600만원의 5년 후 예상 자산 분포
- 1억원 도달 비율
- 탈락 사유
- 전체 실험 원장

최종 보고서는 최고 CAGR 후보만 보여주지 않고 모든 후보의 통과·탈락 근거를 비교한다.

## 10. 코드 경계

구현 단계에서는 기존 라이브 파일에 전략 실험을 직접 누적하지 않는다.

- `backtest-swing.mjs`: 기존 combo-v2 기준선과 공통 실행 경로
- 신규 연구 실행기: 후보 등록, 포트폴리오 결합, 일괄 실행
- 신규 결과 모듈: MC, 스트레스, 등급 판정, 실험 원장
- 신규 테스트: 자본 배분, 리밸런싱, 손실 중단, look-ahead 방지, 판정 경계
- `strategy-contract.mjs`: 최종 통과 전 변경 금지
- `stock-live.mjs`: 최종 통과 전 변경 금지

기존 변동성 스로틀은 shadow 전용 경로를 재사용하며, 실주문 수량에는 연결하지 않는다.

## 11. 실패 처리와 안전 경계

- 데이터 누락이나 기업행사 불확실성은 낙관적 보간 대신 후보 탈락 사유로 남긴다.
- 거래 수가 부족하면 CAGR이 높아도 `SHADOW_ONLY` 이하로 제한한다.
- 한 전략의 실패가 전체 실행을 중단시키지 않도록 후보별 오류를 분리 기록한다.
- 산출물에 설정, 시드, 코드 커밋을 남겨 같은 결과를 재현할 수 있어야 한다.
- VM 배포, SCP, systemd 재시작, 실계좌 주문은 별도 사용자 승인 없이는 수행하지 않는다.

## 12. 완료 조건

연구 구현 완료는 다음 조건을 모두 만족할 때만 선언한다.

1. 최대 9개로 제한된 후보가 동일한 데이터·비용·판정기를 사용한다.
2. 기준선과 각 후보의 결과가 재현된다.
3. MC와 스트레스 결과가 보고서에 포함된다.
4. 생존편향 또는 오염된 평가구간의 한계가 명시된다.
5. 전략별 등급과 탈락 사유가 자동으로 산출된다.
6. 로컬 테스트와 정적 검사가 통과한다.
7. 실계좌와 VM에는 변화가 없다.

이 설계는 1억원 달성을 약속하지 않는다. 정해진 위험 범위 안에서 목표를 달성할 근거가 있는 전략이 실제로 존재하는지를 검증한다.
